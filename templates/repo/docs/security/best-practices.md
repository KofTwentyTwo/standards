# OpenSSF Best Practices assessment

## Project and ownership

For a public open-source Product repository, register its exact canonical URL at
<https://www.bestpractices.dev/en>. Replace `badge.projectUrl` in `assurance.json`
with the actual `https://www.bestpractices.dev/projects/<numeric-id>` URL and add the
provider's real linked badge to the README. Record the owner, review date and next
review within 90 days. Private/Internal scope decisions need a documented rationale.

## Criterion evidence

Use the current [passing criteria](https://www.bestpractices.dev/en/criteria/0).
For each answer, link actual source, policy, test or observed operational evidence.
Separate implemented practice from intentions, pending human attestations, and
justified not-applicable answers. Passing is the target, not an automatic claim
made by a copied template. Record remaining gaps with owners and follow-up dates.

## Maintenance

Reassess at least every 90 days and before each MINOR or MAJOR release. Keep the
provider's answers consistent with this evidence. A registration restriction needs
a dated approved exception; never use another repository's badge or invent an ID.
